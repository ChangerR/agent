# 最终交付范围

建议进入 Draft PR 代码审查，不宣称已完成成熟、全面的真实 workflow 验收。本轮收尾没有新增 API，没有提交、推送或创建 PR。此前 48 次 workflow 探索与获准的 12 次 judge 专项已经分别耗尽并停止；历史 176/188 次提案仅为归档材料，不是继续工作的计划或授权。

## 保留的生产改动

1. 主模型 system 保持固定。计划状态只在变化后作为带 runtime 来源的消息追加；恢复、压缩、只规划、只读任务与父子任务仍由原来的内核限制执行。协议、session schema、历史显示及 fake provider 的修改只是适配这一个消息来源，没有新增 Plan 能力或版本迁移。
2. 审批完整用户授权和固定工具信息前置，操作与风险证据保留，易变历史放在后面。逐字相同的授权和 cwd 使用明确引用；不同来源、历史顺序、不同路径及省略标记仍保留。新增 `review-evidence.ts` 只有一个布局函数，没有通用摘要或压缩框架。
3. 模型证据移除 opaque 调用 ID 和 revision；内核 session/run/config/policy、工具身份、输入、环境及取消状态绑定完整保留，执行前照常重验，没有批准缓存或命令白名单。
4. 轻量观测保留角色、requestId、规范化请求大小、usage 是否实际报告及已知 cache hit/miss。厂商明确字段优先，缺失值不计为零。没有在生产路径增加原始 wire 前缀缓存、请求正文日志、回放或实验调度器。
5. 保留已确认的限制审计修复：root 计划门拒绝不再误记为 child_restriction，policy 后、judge 前的二次限制拒绝补全同一绑定审计。原因使用固定白名单，避免路径或任务正文进入 reasonCode；权限结果未改变。

## 本轮有限简化与修复

- 主模型和 reviewer 各只累计一份 reportedUsage，在发事件时补齐原有数值字段；cache 指标先按实际报告的字段计算，不把缺失当作零。
- reviewer 请求 JSON 大小只计算一次，预算与统计共用结果。
- size/evidenceBytes 仅随 model_request 记录，model_usage 通过 requestId 关联；child 同样保留关联，不重复携带请求大小证据。
- 修复独立审查发现的 OpenAI 边界：cached_tokens 为 null 时转为未知，避免将 null usage 传入严格 reviewer 而触发回退。已有用例扩为 undefined/null 两种情况，没有增加测试框架。这个边界是静态确认的代码缺陷，尚未在真实 API 样本中出现。
